# 极思G界址点互转工具 — 完整功能 PRD

日期：2026-06-11
状态：初稿

## Problem Statement

测绘与国土行业需要在 SHP/GDB 矢量数据和标准界址点 TXT 文件之间频繁互转。现有工具要么依赖 ArcPy（体积大、学习成本高），要么是老旧的 Delphi 程序（仅支持政府格式 SHP）。用户需要一款轻量、开箱即用、支持主流坐标系的桌面互转工具。

## Solution

基于 Tauri v2 的桌面应用：Rust 后端处理 SHP/DBF/PRJ/TXT/GDB 的读写与转换，Vite 打包的单文件 HTML 前端提供双模式（面→TXT / TXT→面）操作界面。支持拖拽导入、字段自动匹配、表头自动识别、实时预览。

## Implementation Decisions

### 架构模块

- **前端模块**（index.html + src/main.js）：单文件 HTML + 内联 JS，Vite vite-plugin-singlefile 打包
- **Rust 后端模块**：lib.rs（IPC 命令入口）、shp.rs（SHP/DBF/PRJ 读写）、txt.rs（TXT 解析/生成）、gdb.rs（GDB 读写）、convert.rs（转换编排）
- **对话框模块**：Tauri dialog 插件处理文件/文件夹选择
- **文件系统模块**：Tauri fs 插件处理文件操作

### 面→TXT 转换流程

1. 导入 SHP（读取 .shp + .dbf + .prj）或 GDB（读取要素类）
2. **GDB 图层选择**：导入 GDB 后，中央区域展示所有面图层，用户勾选要转换的图层
3. 自动匹配字段（DKMC→MC→NAME 等优先级规则）
4. 自动填充表头（从 .prj WKT 解析坐标系信息）
5. 用户可覆盖配置（预设方案 / 手动修改）
6. 实时预览 TXT 输出（150ms debounce，前 3 地块 × 20 坐标点）
7. **输出路径**：左栏最下方显示，默认在第一个数据文件所在目录下创建"临时数据"文件夹，用户可修改
8. 点击"开始转换"直接输出到该路径，不再弹出文件夹选择框

### TXT→面 转换流程

1. 导入 TXT（解析 [属性描述] + [地块坐标]）
2. 显示解析日志（坐标系、地块列表、统计信息）
3. 用户选择输出格式（**默认 SHP**）和文件组织方式
4. **输出路径**：默认在第一个 TXT 文件所在目录下创建"临时数据"文件夹，用户可修改
5. 点击"导出"直接输出到该路径，不再弹出文件夹选择框
6. 执行转换：解析坐标 → 构建几何 → 写入 SHP/GDB

### GDB 导入改进（面→TXT）

- 导入 GDB 后，在中央预览区展示所有面图层列表
- 每个图层显示：图层名、要素数、字段列表
- 用户通过复选框勾选要转换的图层
- 未勾选的图层不参与转换
- 只展示面类型的要素类（Polygon / MultiPolygon）

### 导出流程改进（TXT→面）

- 移除输出目录选择弹窗
- 点击"导出"按钮直接执行转换
- 输出路径：TXT 文件所在目录 → "临时数据"文件夹
- 文件命名：以 TXT 文件名命名（如 `xxx.shp`、`xxx.gdb`）
- 若"临时数据"文件夹不存在则自动创建
- 若文件已存在则覆盖（用户需自行管理版本）

### 坐标系支持

- 2000国家大地坐标系（默认）
- 1980西安坐标系
- 1954北京坐标系
- WGS84坐标系

### 坐标格式

- SHP 存储 (X, Y) = (easting, northing)
- TXT 存储 (Y, X) = (northing, easting)
- 转换层自动交换坐标顺序

### TXT 格式规范

- 坐标行：`J序号,1,Y坐标,X坐标`
- 地块元数据行以 `,@` 结尾
- 坐标系字符串必须精确匹配预设值

### DBF 写入

- 手动二进制写入（避免 dbase crate API 问题）
- 字段偏移必须是 4 字节（LE），不能是 2 字节

### 前端技术要点

- ES module import 由 Vite 在构建时内联
- 运行时使用 `window.__TAURI__` API
- 函数导出到 `window.*` 供 HTML onclick 使用
- 事件委托处理动态元素（文件列表删除按钮、预设芯片）
- 拖拽导入（SHP 和 TXT 分别支持）

## Out of Scope

1. **政府格式 SHP**：`test_data/` 中的 .shp 文件使用非标准格式（magic ≠ 9994），标准库无法读取
2. **GDB 写入兼容性**：最小化 OpenFileGDB 实现，可能与某些 ArcGIS 版本不兼容
3. **MSI 打包**：WiX 工具在某些 Windows 配置上可能失败，不影响 .exe 输出
4. **离线字体**：Google Fonts CDN 加载，离线环境可能回退到系统字体
5. **缓冲区处理**：预留了参数接口，但尚未引入计算几何库实现实际的多边形膨胀/收缩
6. **多部件多边形**：当前按单部件处理
